# tooling (cross-cutting)

<!-- When: git, gh, worktree, or agent-host trouble. Area tooling (package managers, linters): <area>/docs/learnings/tooling.md. -->

- **Verify a fresh worktree's base against `origin/main`: `git fetch --prune origin && git rev-list --count HEAD..origin/main`.** — agent hosts can branch new worktrees from a stale remote-tracking ref (seen: T3 Code branching from a deleted `origin/master` while `origin/main` was ahead). build-loop STARTUP fast-forwards fresh branches. src: codeangel seed
- **`git worktree remove` (no `--force`) succeeds when only ignored files remain and deletes them; it refuses on untracked or modified files.** — ignored generated data (downloads, generated media, `.env`) is silently destroyed → inspect `git status --porcelain --ignored` first; worktree-cleanup only removes what `[worktrees] disposable` allows. src: codeangel seed
- **Don't commit symlinks.** — Git for Windows defaults to `core.symlinks=false` and native symlinks need Developer Mode; a committed symlink checks out as a one-line text file. Skills use generated shims instead (`docs/ai/agent-docs.md` → Skills). src: codeangel seed
- **On Windows, `gh` not recognized can mean `C:\Program Files\GitHub CLI` is missing from PATH.** — the CLI may already be installed and logged in; prepend that directory, then `gh auth status`. src: CAM-6
- **Renaming the folder that holds the skills (`.codeangel/`): delete `.claude/skills/` before `codeangel sync`.** — old shims carry the previous `GENERATED by <old path>/sync-shims.py` marker, so the new sync treats them as hand-written and fails with "collides". Rename last, then call `T` and `sync-shims.py` through the new path. src: CAM-10
- **On Windows with `core.autocrlf=true`, `git status` lists files as modified after a bulk `sed -i` even when nothing changed.** — judge the change by `git diff --stat`, not `git status`; the CRLF-only entries have no content diff and are not staged. src: CAM-10
- **Tests that import a payload script with `importlib` must set `sys.dont_write_bytecode` first.** — the import drops a `__pycache__/*.pyc` into `src/codeangel/payload/`, and the payload scans (`test_managed_files_are_project_agnostic`, `test_build_stages_reference_code_standards`) then die with `UnicodeDecodeError` reading it. `tests/support.load_script` does this; delete any stray `payload/**/__pycache__` before re-running. src: CAM-7
- **`ruff format src tests` also rewrites the shipped payload scripts under `payload/managed/` (only `presets/` is excluded); rerun `codeangel update` on this repo afterwards.** — the installed copy in `.codeangel/` and its lock hashes otherwise lag the payload. src: CAM-13
- **Test new preset Python in a generated project (`init` → `add` → `poetry install` → `pytest` + `ruff`), not only in this repo.** — presets are excluded from this repo's gates; the django-drf session helper passed review until the generated run showed that calling `set_unusable_password()` on every issue rotates the password hash and invalidates the user's earlier sessions (set it only on creation). src: CAM-13
- **Don't write Python or text containing `\n` / `\x00` through a Bash heredoc in this harness; use the Edit / Write tools.** — backslash escapes are unescaped once before Python sees them, so a `"\n"` in the heredoc became a real newline (syntax error) and `"\x00"` put NUL bytes in a test file that Edit / Write then refused to open. src: CAM-16
- **A `[proof: …]` tag takes a reason only for `none`; `api`/`ui`/`cli` (combined with `+`) must stand alone, e.g. `[proof: cli]`.** — `[proof: cli — why]` makes `T go planned` report "AC-n has no [proof: …] tag", which reads as a missing tag. Put the how-to-prove detail in the AC text instead. src: CAM-18
- **Check GitHub rendering with `gh api markdown -f mode=gfm -f context=<owner/repo> -f text=…` before relying on HTML in a PR body.** — it returns the sanitised HTML without posting; it showed `<video src>` for repository files is stripped while images and links survive. src: CAM-19
- **The payload's `transition.py` is linted too: keep `main()` under the statement cap (`PLR0915`) by registering commands in `build_parser()`.** — adding one more sub-command pushed `main` to 51 statements and failed `ruff check`. src: CAM-19
